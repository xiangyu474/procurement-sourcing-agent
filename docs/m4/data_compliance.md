# M4 数据合规说明

面向评委与合规审查。说明这个系统用了哪些数据、数据存在谁那里、哪些数据不会互相混。

## 数据从哪来

| 数据 | 来源 | 存在哪 |
| --- | --- | --- |
| 采购需求 | 演示人自己输入的文字，或演示人上传的官方 PPTX | D1，按访客会话归属 |
| 供应来源与型号 | 公开网页：厂商规格页、技术参数页等 | 证据快照存 R2，元数据存 D1 |
| 网页快照 | 抓取当时页面的正文，另存内容哈希与地址 | R2 私有桶 |
| 技术声明 | 模型从快照正文里读出的数值，带引文 | D1 |
| 历史采购记录（可选） | 演示人上传的 XLSX | D1，按访客会话归属 |
| 模型调用 | 走 OpenAI 兼容接口，地址由环境变量配置 | 不落盘 |
| 检索 | 公开网页检索接口（Tavily Search/Extract） | 检索结果进证据快照 |

模型调用与检索都不带访客的凭证，只带系统自己的密钥。密钥只在 Worker 和容器的服务端环境里，**不进浏览器、不进 Git、不进报告**。

## 浏览器里有什么

- 一个 HttpOnly Cookie：Worker 签发的访客会话，24 小时有效，签名密钥只在服务端。
- 没有任何 Bearer 凭证。访客不需要登录，也不需要注册。
- 前端不保存需求文本，不保存模型结果。刷新后从服务端重新读。

## 访客之间互相看不见

访客会话是归属的边界。项目、运行、分析、报告、下载都按会话校验归属：

- 访客 A 的会话读访客 B 的项目、运行、分析、报告、下载，全部返回 404。
- 访客的账号之间没有任何共享状态。

2026-11-04 与 11-05 的实网验收都验过这一条。

## 限流与滥用防护

| 防护 | 做法 |
| --- | --- |
| 会话创建 | 全局每小时 60 次，每 IP 每小时 10 次 |
| 已认证请求 | 全局每分钟 600 次，每会话每分钟 120 次 |
| 任务并发 | 全局 2 个，每访客 1 个 |
| 访客日额度 | 16 个预算单位、6 次启动 |
| 全局日额度 | 80 个预算单位 |

预算单位是并发与日量的粗略代理，**不是模型调用次数，也不是金额**。实际模型与搜索调用仍受研究阶段内部的上限约束。

IP 只存 HMAC，不存原始 IP。同一区域的 Worker 子请求可能改写 IP，所以 IP 只当滥用信号，不当身份。

## 模拟历史与真实供应来源的隔离

导入的历史 Excel 里的供应商是模拟数据，有自己的命名空间：

- 模拟供应商**永远不会**被自动映射到现实企业。
- 按供应商名把历史和公网数据 JOIN 是被禁止的。
- 历史与公网只按**确认过的产品等价关系**融合。同名供应商但没有确认过等价的两条记录不会被合并，未经确认的关系不进索引。

所以页面上出现的供应来源来自公开网页，不来自那份模拟历史。

## 结论怎么被约束

- 技术结论只用快照正文里的数值，按单位换算白名单逐条算。对齐不上、单位换不了、声明没来源，三种情况都给 UNKNOWN 并写明缺什么。**系统不用「同品类」「同系列」补齐。**
- 建议档位要同时满足：门禁通过、`SHORTLIST`、`VERIFIED_PASS`、硬性约束 `PASS`。少一条就不是建议询价。
- 原始英文理由没有逐条翻译时，页面显示结构化中文摘要，并写明「还有原始信息待核对」，不把摘要当完整翻译。

## 报告里有什么

正式 DOCX 报告与页面是同一份冻结结论（同一 `decision_version`），包含：

- 需求摘要与每条约束的原文引用
- 候选与型号：供应商、型号、阶段、技术结论、建议、证据数
- 逐约束的判定：计算式、结果、原因码、证据 ID
- 价格与口径：历史口径范围与统计、各口径的最低价与可比性
- 询价建议三档
- 证据引用：证据 ID、来源地址、摘录、内容哈希

来源地址与内容哈希都在，第三方可以复核每一次引用。

## 还没做的

- 没有逐次模型调用计费。预算单位是并发与日量的代理。
- 访客会话的 IP 在同区域 Worker 子请求中可能改写，只能当滥用信号。
- 技术核验的语义对齐依赖模型判断。模型的语义拒绝保留为 UNKNOWN，代码只纠正方法标注和缺失的 claim id，不把不确定变成通过。
