# F1 设计评审与三个布局方向

评审对象是当前分支上的 F1 工作区，不是后端计划。这次不改 `frontend/src`，也不做 F2–F4。三个方向是可点击的静态原型，数据在 `frontend/prototypes/fixtures.js`，文件头标明 `FIXTURE`。它们不被 `frontend/index.html` 引用，不在 `tsconfig.json` 的 `include` 里，因此不进入默认构建。

打开 `frontend/prototypes/index.html`。顶栏可以切换：空项目、填写需求、寻源中、已结束、部分完成、未能完成、访问被拒绝。点一行候选，展开来源。截图去掉了顶栏，只留界面本身。

## 1. 对当前 F1 的评价

F1 把真实接口走通了，界面也没有口号和指标卡。问题是它还是一张「表单加一段状态」，没有为后面的候选、证据和报告留出结构。

### 信息层次

左栏把「创建」「项目列表」「粘贴编号打开」放在同一权重。编号输入是缺列表接口时的补救，不该和项目名称抢第一眼。

右栏从上到下是：标题、一句可能很长的提示、无标签的文本框、两个上传、一份子弹列表、主按钮、活动句、错误、运行状态。子弹列表里同时有「文字已提交」「文件已接收」「已整理 N 条」。接收文件和整理出采购项不是同一件事，现在看起来像同一份清单。

运行编号用完整 UUID，和状态句一样醒目。编号对排查有用，不该成为这一屏的第二标题。

### 布局

主栏限制在 880px，1440 宽的屏幕右侧是空的灰。现在只有一张表单，所以空着还能接受。候选表需要横向空间，这道上限会变成障碍。

空项目时，主区只有「创建或打开一个项目」，创建控件在左栏。两处没有对齐，第一次使用要自己发现左上角。

访问被拒绝是一条左边线，位置正确，没有把整页做成错误页。这一点应保留。

### 字体和间距

正文字号 15px、行高 1.5，中文长名称能换行，这是对的。行高对多行供应商名偏紧，连续三行时会贴在一起。

字号只有 22 / 18 / 15 / 13 四档，没有写成变量。按钮、边框、警告色散落在一份全局 CSS 里，已经为了「创建」二字被挤成竖排改过一次 `white-space`。后面每加一块结果，都会继续打补丁。

`overflow-wrap: anywhere` 能保住布局，但用在型号上会把 `DS-2CD2T45FWD-I5` 从连字符拆开。供应商名可以断，型号和「建议先询价」「还不能判断」不应断。

### 状态

| 状态 | 现在 | 问题 |
| --- | --- | --- |
| 空项目 | 一句提示 | 和创建动作分开 |
| 填写中 | 文本框一直在 | 和后面的结果没有分界 |
| 寻源中 | 标题改成阶段名，表单禁用 | 页面仍然是一张表单，进行中不够明确 |
| 部分完成 | 有说明，保留已有信息 | 文案是对的；下面没有地方放已经得到的候选 |
| 未能完成 | 红左边线 | 清楚 |
| 访问被拒绝 | 一句「访问被拒绝。」 | 清楚，不要再解释成登录营销页 |

部分完成和未能完成的差别已经有了：前者说明结果还在，后者说明这次没有完成。F2 必须让部分完成下面仍然出现已经得到的行，未能完成下面不编造行。

### 操作路径

创建、输入、上传后立即显示「已接收」、历史导入单独一步、再点开始寻源。这个顺序和接口一致，不要改成上传即导入，也不要把整理需求藏进一个假进度条。

现在「正在整理需求」只是按钮上方的一句话，和「正在启动寻源」同一位置。用户分得清，但刷新之后如果整理还在进行，页面上没有一个稳定的位置说明「人在等的是整理，不是寻源」。

结束后主按钮变成「再次寻源」。这是一次新的运行，文案是诚实的。

### 接到 F2、F3 时会怎样

若把长名单接在表单下面：

- 需求表单和候选抢同一列，看结果时还要滚过文本框。
- `长名单`、`建议先询价`、`满足`、`不满足`、`还不能判断` 若再做成子弹，无法并排比较。
- 价格若做成可排序的列，会被读成最低价榜。公网参考价、计划预算、历史成交价、正式询价报价必须写在被点开的那一行里，用句子说明能不能比。
- 证据没有「当前选中的一行」。全部展开会变成一长页；不提供选中，就无法做渐进披露。
- 下载必须钉在当前这次运行上。现在 `RunPanel` 只显示状态和编号，没有一个位置写「下载这一版」或「报告还没有生成」。

### 代码

该留的：

- `frontend/src/api/client.ts` 只做请求和窄解析，不带凭证。
- `frontend/src/api/adapter.ts` 把运行状态和错误码翻成中文，不展示内部角色名。
- `frontend/src/components/RunPanel.tsx`、`ProjectNav.tsx` 是纯展示。
- `frontend/src/storage.ts` 只记本机项目编号，没有假装成服务端列表。

该在 F2 前拆开的：

- `useWorkspace.ts` 约 400 行，同时管本机存储、中止、整理轮询、运行轮询、上传、导入和错误。候选再塞进来，这个函数会无法读。
- `App.tsx` 同时管布局、文件输入重置和全部区域。结果表没有可以插入的空位。
- `labels.ts` 从 `useWorkspace.ts` 引入 `HistoryNote`，展示文案依赖了状态钩子的类型。
- `styles.css` 一份到底，没有间距、颜色、字号变量。

不要做的：引入另一套状态库，重写 `ApiClient`，或为了 F2 先改网关。

改动面：样式变量和壳层是移动 JSX 和 CSS。拆钩子要重测创建、上传、开始、刷新，这是 F2 前唯一涉及行为的重构。

## 2. 三个方向

三者都遵守同一约束：没有首屏口号、指标卡、装饰图、嵌套卡片和内部术语。价格不排成最低价。长名单不叫推荐。`还不能判断` 不是失败。报告只属于当前看到的那一次运行。

夹具里的三行是故意分开的：一行长名单且还不能判断，一行长名单且不满足，一行建议先询价且满足。部分完成只有两行，其中一行没有打开到来源。

### 备忘录

左栏只做项目索引。右栏是一条最多约 720px 的阅读列，像一份往下写的寻源记录：需求、运行、候选、来源、下载。

```text
项目索引          标题
创建              需求缩成一行
名称 + 状态       寻源已结束
                  运行 …
                  下载这一版
                  候选
                  供应商 | 型号 | 阶段 | 技术
                  来源与价格句子
```

选中一行后，来源接在该行下面，不另开一栏。窄屏时索引移到上面，行改成上下堆叠。

取舍：读一条证据很顺，句子比表格难被误当成排名。比较两三家时要来回滚动，型号和阶段挤在阅读列的同一行里。1440 宽的屏幕有一大半用不上。部分完成时，说明和残缺的列表仍在同一条阅读流里，这是优点。

工作量：F1 的单栏可以迁过来，但 F2 的表要改成文档行，比较场景会反复改列宽。

### 对照

左栏仍是项目。主区在没有结果时是需求；有结果后，需求收成一行，下面是一张只有横向分隔线的表：供应商、型号、阶段、技术。右侧一栏是选中行的来源、摘录和四种价格口径。没有价格列，避免被读成排序。

```text
项目                 标题                     下载这一版
名称 + 状态          需求 · 修订 1
                     寻源已结束
                     供应商 | 型号 | 阶段 | 技术    来源
                     选中行                        摘录
                                                   公网参考价 …
                                                   计划预算 …
```

窄屏时表改成每行一组字段，来源接到选中行下面。

取舍：桌面宽度用在「列表还在，同时读证据」。长名称在供应商列里换行，阶段和技术不换行。右侧是一栏文字，不是卡片。代价是它比备忘录更像工具，必须守住「只有横线、没有框套框」。部分完成时，说明在表上方，已有的行留在表里，没有来源的行在右侧写明没打开到。未能完成不画行。

工作量：要先有一个带「详情空位」的壳，再把表现在的表单从 `App.tsx` 挪走。F2 的主要新文件是表和右侧来源，而不是再改整页。

### 队列

没有左栏。页顶是三个词：需求、寻源、结果。当前这一步用字重标出，其余变灰。项目是顶上的两行名称。候选是通栏列表，来源是选中行下面的一条灰底，左右与正文对齐，没有圆角和阴影。

```text
需求    寻源    结果
项目名称

标题
寻源已结束
下载这一版
供应商
型号 · 阶段 · 技术
[灰底：来源与价格]
下一行
```

取舍：手机上最干净，来源不会挤在侧栏。三个步骤容易被看成向导，好像必须走完才能回头看需求；实际上需求、运行和结果是同时存在的。桌面上列表和来源上下排，比较相邻两行时来源会把它们隔开。项目切换比左栏弱。

工作量：F1 的左栏要拆掉，步骤状态要新做一套，和现有「名称 + 状态」列表重复。

## 3. 建议

采用**对照**。

备忘录最不像仪表盘，但候选一多，阅读列里的四列就会挤，证据把下一行顶走。队列在手机上清楚，却把同时存在的三块内容装进了步骤。对照让列表留在原地，证据按行打开，价格只出现在证据里。窄屏时的堆叠已经写在原型里，不需要另做一套信息架构。

从备忘录带走的只有证据的写法：来源、摘录、价格都是句子。从队列带走的是窄屏规则：详情跟在选中行下面，不维持右侧空栏。

F2 之前做这些，不做别的。都不改网关和 Python。

| 顺序 | 文件 | 做什么 |
| --- | --- | --- |
| 1 | 新建 `frontend/src/styles/tokens.css`，改 `frontend/src/main.tsx` 引入 | 只放颜色、字号、行高、间距。正文 15px，行高 1.6。警告色沿用现在的赭色和红色左边线 |
| 2 | 改 `frontend/src/styles.css` | 改成壳层：左栏、工作区、有结果时的左右分栏。删掉 880px 上限。型号和技术状态不使用 `anywhere` 断行 |
| 3 | 新建 `frontend/src/components/WorkspaceShell.tsx`，把 `App.tsx` 收成组合 | 壳提供导航、主区、详情空位。空位在没有候选时不渲染 |
| 4 | 新建 `frontend/src/components/DemandForm.tsx` | 从 `App.tsx` 挪走文本框、上传、已接收、导入和开始按钮。有结果后默认收成一行，可展开 |
| 5 | 新建 `frontend/src/view/candidates.ts` | 阶段、技术结论、四种价格口径的中文。只做显示映射，不计算结论。`adapter.ts` 继续只管运行和错误 |
| 6 | 拆 `frontend/src/workspace/useWorkspace.ts` | `useProjectSession` 管项目、草稿、上传、导入。运行轮询留在原处或 `useRunWatch`。候选的读取留到 F2，挂在运行编号上，不写进上传流程 |
| 7 | 改 `frontend/src/workspace/labels.ts` | 去掉对钩子文件的类型依赖，历史文件那几句搬到 `view` 或就地定义 |

`RunPanel.tsx` 和 `ProjectNav.tsx` 留着。`ProjectNav` 把编号输入留在列表下方，在列表接口出现之前不把它设计成主路径。`client.ts` 不动。

F2 再新增 `CandidateTable.tsx` 和 `EvidencePane.tsx`，放进壳的两个空位。F3 的下载是表头右侧的一个动作：有当前运行的报告才显示「下载这一版」，否则显示「报告还没有生成」。不要新开页面。
