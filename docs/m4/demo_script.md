# M4 演示脚本（三分钟）

面向演示人。目标是让评委在公开地址上走完一条真实链路，并看清三件事：**结论有来源、结论分档、结论可下载可复核**。

演示地址：`https://procurement-sourcing-agent.com`（页面与 API 同源，访客会话自动建立）。

## 演示前 10 分钟

1. 用**无痕窗口**打开演示地址。已有会话的浏览器也能用，但无痕窗口能证明「不需要登录」。
2. 确认网络能打开这个地址。容器是按需启动的，第一次点「开始分析」可能多等一两分钟。
3. 准备两份需求：官方 PPTX 一份，文字需求一份。**以实测跑出 PASS 的那次为准**（`docs/m4/backend_contract_response.md` §7.7 更正一：决定结论的是这次研究引了哪一行，不是文字还是 PPTX）。
4. 演示期间不要在同一网络里跑别的分析。访客额度是每日 16 单位、6 次启动，一次完整分析占 5 个单位。

## 0:00 — 访客身份（15 秒）

打开页面。右上角没有登录框，左侧项目栏是空的。

> 「评委打开网页就能用，不需要注册。身份是一个 Worker 签发的 HttpOnly Cookie，浏览器里没有凭证。两个访客互相看不到对方的项目。」

## 0:15 — 建项目、填需求（30 秒）

在「新项目名称」里填一个能看出业务的名字，点「创建」。在需求框里写采购需求，或上传 PPTX。

> 「需求可以是文字，也可以是官方的 PPTX。系统先把需求整理成结构化的采购项：品名、数量、硬性约束。」

点「开始分析」。页面出现「正在整理需求」，下面一行写「已整理 N 条采购项」。

> 「整理结果会写在这里：几条采购项、哪些字段还需要确认。」

## 0:45 — 一次点击与进度（60 秒）

点「开始分析」之后**不要再点**。进度行依次出现：

| 屏幕上 | 实际在做什么 |
| --- | --- |
| 正在整理需求 | 把需求文字整理成结构化采购项 |
| 正在寻找供应商 | 公开检索厂商规格页，把网页快照存下来 |
| 正在核对技术与价格 | 逐条约束对照型号声明，算出 PASS / FAIL / UNKNOWN |
| 正在整理采购建议 | 通过门禁的建议、待补证的、建议排除的 |
| 正在生成报告 | 用同一份冻结结论生成正式 DOCX |

> 「这一次点击会跑完整个流程。中间每一步的进度都来自后端的状态接口，前端不自己编进度。」

**这一段要花 9 到 12 分钟**，是演示里最长的一段。可用的话先跑一次，把结果留在浏览器里，演示时直接刷新看结果。

## 1:45 — 结果（60 秒）

结果表一行是「需求 × 型号」。点「展开来源」看这一行背后的供应来源。

指着四列说：

> 「供应商、型号、阶段、技术结论。**阶段是采购建议，技术结论是核验结果，两回事**：技术不满足的型号不会因为建议好看就进短名单。」

点一行，右侧详情栏从上往下：

- 结论摘要（中文）
- 还差什么、下一步
- 判断句：要求多少、读到了多少
- 来源与摘录、来源链接

> 「结论后面的每一条判断都能点开来源，看到的是当时的网页快照原文，不是模型的复述。」

再指覆盖提示（如果有）：

> 「后端会说明这次研究的覆盖情况，比如『只找到一个型号』或者『研究用完了预算』。」

## 2:45 — 价格口径与下载（30 秒）

指详情栏底部的价格四行。

> 「四种价格分开写：计划单价或计划预算、历史成交价、公网参考价、正式报价。**网页标价不是正式报价**，全表概览不能当单品基准，所以历史口径不对时这里只写口径，不写节支。」

点右上角「下载这一版」。

> 「下载的是 DOCX 正式报告，和页面上这一版是同一个决策版本，不是重新算的。」

刷新页面。

> 「刷新之后还是这一版。切换历史运行，候选、判定、价格、报告一起换，不会把新的判断混进旧的运行。」

## 备用：分析失败或结果全是「还不能判断」

这两种都出现过，不是前端故障。

**失败**：页面显示一句中文原因（研究失败、模型超时、决策没生成），不显示结果，也不显示下载按钮。

> 「这次分析没完成。失败原因后端给的是公开错误码，前端翻译成一句话，可以直接再试一次。」

**全是「还不能判断」**：说明这次研究没引到写明输出分辨率的规格行。模型按规则拒绝把宣传页或型号名里的 5MP 当成测量。

> 「技术核验宁可留 UNKNOWN 也不用同品类同系列补齐。这是刻意的：宁可说不知道，不能猜。」

这两种情况下换另一份素材重跑，或用提前跑好的那次结果。

## 已知边界（被问到时照实说）

- 一次完整分析 9 到 12 分钟，研究占大头。
- 访客额度是每日 16 个预算单位、6 次启动。单位是并发与日量的粗略代理，**不是模型调用次数，也不是金额**。
- 两个访客互相看不见：项目、运行、分析、报告、下载全部 404。
- 历史导入里的模拟供应商有自己的命名空间，不会被映射到现实企业；历史与公网只按确认过的产品等价关系融合。
- UNKNOWN 是「还不能判断」，不是不合格；长名单不是推荐；建议询价也不是准入或中标。
