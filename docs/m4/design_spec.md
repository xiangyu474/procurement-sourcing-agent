# 对照：签收用设计说明

负责人已选定对照。本文件是这一方向的视觉和组件规范。原型在 `frontend/prototypes/inspector.html`，夹具在 `fixtures.js`（文件头标明 `FIXTURE`，不进入默认构建）。这次没有改 `frontend/src`，也没有开始 F2。

打开原型后用顶栏切换状态。截图去掉了顶栏。

## 原则

任务优先。没有口号、指标卡、装饰图、嵌套卡片和内部术语。说明只出现在异常或还不能做的动作上：部分完成、未能完成、访问被拒绝、报告还没有生成。

长名单不是推荐。建议先询价不是准入或中标。还不能判断不是不满足，也不是满足。四种价格不排成最低价。网页标价写成公网参考价，不写成正式报价。

中文字号和行高：

| 用途 | 字号 | 行高 |
| --- | --- | --- |
| 表头、价格类型旁的小标题 | 12px | 1.45 |
| 表格、项目列表、按钮 | 14px | 1.6 |

## 布局

桌面：左栏 248px，右侧工作区占满剩余宽度，页面至少一屏高，底色是白。

有候选时，工作区下半是表加 360px 详情。没有候选时不留空的详情栏。

窄于 800px：项目栏在上，表改成每行一组字段，详情接到选中行下面，并用同一条强调色顶边连接。

选中行是浅底加左侧 3px 强调色，不是粗黑竖线。详情栏用同一浅底和同一条色边。整行可点。未选中时，详情写「选择一行查看来源。」

## 组件和状态

**项目栏。** 顶部一个输入框，占位符「新项目名称」，旁边是「创建」。列表只显示名称和状态。当前项用浅底和强调色左边线。

「用编号打开」收在栏底的折叠里，默认合上。这是没有项目列表接口时的补救，不放在主路径上。

**需求。** 还没开始寻源时，文本框占位符是「填写采购需求」。上传后另起一行写「已接收」，和「已整理」不要混成同一种子弹。历史导入是单独的按钮。主按钮只有「开始寻源」。

有结果之后，需求收成一行「需求 · 修订 1 · …」，可展开。

**运行。** 主区用时间标明是哪一次，例如「10月31日 09:16 的寻源」。进行中写「10月31日 09:16 开始」。完整编号只放在「过程记录」里。

| 运行状态 | 呈现 |
| --- | --- |
| 进行中 | 蓝字「正在查阅公开资料」。不解释 |
| 已结束 | 黑字「寻源已结束」。不用绿色，避免被看成技术通过 |
| 部分完成 | 褐字，加一句「已保留目前得到的结果。……」。已有的行留下 |
| 未能完成 | 红字，加一句原因。不编造候选行 |

**阶段和技术。** 字本身带颜色，不做色块。

| 词 | 颜色 | 不要做成 |
| --- | --- | --- |
| 长名单 | 次字灰 | 推荐、通过 |
| 建议先询价 | 蓝 | 中标、准入 |
| 满足 | 绿 | — |
| 不满足 | 红 | — |
| 还不能判断 | 蓝灰 | 错误、不满足、满足 |

**详情，自上而下。** 型号、供应商全名、阶段 · 技术结论、阶段这句话的含义、判断句、来源和日期、摘录、价格。

价格固定四个名称，按这个顺序，没有的写「还没有」：

1. 计划预算
2. 历史成交价
3. 公网参考价
4. 正式报价

公网参考价的句子里写明它是网页标价，不是正式报价。口径不同就写不能比，不排序。

**下载这一版。** 放在标题右侧，下划线文字按钮，不是主按钮。

| 情况 | 按钮 |
| --- | --- |
| 这一版报告已经生成 | 可点 |
| 寻源已结束或只部分完成，但报告还没有 | 同一位置，禁用，旁边写「报告还没有生成」 |
| 进行中、尚未运行、未能完成 | 不显示 |

访问被拒绝只在工作区放一句「访问被拒绝。」，左边红线。不做成登录页。
